## 1. Amazon Bedrock embeddings with a Bedrock API key

### Authentication, scope and version support

- **Documentation:** Set `AWS_BEARER_TOKEN_BEDROCK` in the service process environment or send the key in `Authorization: Bearer …`. AWS's Python example creates an ordinary `boto3.client('bedrock-runtime', region_name=...)`; it does not pass the API key as an AWS access-key ID or sign it manually. [AWS usage](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-use.html)
- **Documentation:** Short-term keys expire at the earlier of 12 hours and the generating principal's session expiry, inherit that principal's permissions, and work only in the generating Region. Long-term keys have a chosen expiry and an underlying IAM user/policies; AWS recommends them only for exploration. [How keys work](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-how.html)
- **Documentation:** Keys are limited to Bedrock and Bedrock Runtime actions; explicitly excluded are `InvokeModelWithBidirectionalStream`, Bedrock Agents/Agents Runtime, and Data Automation/runtime APIs. This is not a universal AWS credential. [Supported scope](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-supported.html)
- **Inference:** `InvokeModel` embedding requests are permitted by that API boundary, subject to the key's permissions and model/Region availability; this is not permission to call S3, nor proof that an account has model access. AWS's Embed v4 model card itself demonstrates bearer configuration followed by `invoke_model`. [Embed v4 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-cohere-embed-v4.html), [key scope](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-supported.html)
- **Documentation:** Supported SDK languages listed are Python, JavaScript and Java. Key Regions listed are `ap-northeast-{1,2,3}`, `ap-south-{1,2}`, `ap-southeast-{1,2}`, `ca-central-1`, `eu-central-{1,2}`, `eu-north-1`, `eu-south-{1,2}`, `eu-west-{1,2,3}`, `sa-east-1`, `us-east-1`, `us-west-2`, `us-gov-east-1`, `us-gov-west-1`. Model availability is a separate table; notably key support does not imply all model Regions support keys. [Key Regions/SDKs](https://docs.aws.amazon.com/bedrock/latest/userguide/api-keys-supported.html)

- **Inference — authentication compatibility:** For existing Titan/1024, no model-selection or vector-schema change follows merely from using a bearer key. ## 2. Generative UI for chat and advisor

### Current AI SDK meaning, client and server requirements

**Documentation/registry:** Current official pages label themselves v7; npm's `latest` resolved `ai=7.0.166`, `@ai-sdk/react=4.0.170`. The React package depends on `ai=7.0.166`, SWR and other SDK packages, and peers React `^18 || ~19.0.1 || ~19.1.2 || ^19.2.1`. Do not assume the React integration's major matches the core package's major. [Docs](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces), [ai registry](https://registry.npmjs.org/ai/latest), [React registry](https://registry.npmjs.org/@ai-sdk/react/latest)

**Documentation:** Generative UI connects model-selected tools/results to predefined React components. `useChat` yields messages with `parts`; switch on `part.type`, including typed `tool-${toolName}`, then render states such as `input-available`, `output-available`, `output-error`. It does not require executing arbitrary model-generated JSX. [Generative UI guide](https://ai-sdk.dev/docs/ai-sdk-ui/generative-user-interfaces)

**Documentation:** `useChat` comes from `@ai-sdk/react`; `DefaultChatTransport` from `ai` defaults to POST `/api/chat`, with configurable URL, headers, credentials, body and request transformation. **Source:** HTTP transport accepts custom `fetch`; its default response parser expects JSON SSE chunks validated against `uiMessageChunkSchema`. Changing only `fetch` or endpoint does not make an ordinary JSON envelope into a valid stream. [Transport](https://ai-sdk.dev/docs/ai-sdk-ui/transport), [HTTP transport source](https://github.com/vercel/ai/blob/main/packages/ai/src/ui/http-chat-transport.ts), [default parser](https://github.com/vercel/ai/blob/main/packages/ai/src/ui/default-chat-transport.ts)

**Documentation/inference:** The wire contract is language-neutral; the docs explicitly link a Python FastAPI backend example. NestJS is already Node-based and can emit it too; neither Next.js nor a model call implemented in JavaScript is required. Every intermediary would have to forward a stream rather than buffer/JSON-decode the entire response for incremental delivery. [Protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol), [official FastAPI example](https://github.com/vercel/ai/tree/main/examples/next-fastapi)

**Documentation:** UI message data uses SSE with `x-vercel-ai-ui-message-stream: v1`. Text/reasoning blocks use ID-linked start/delta/end; tool calls have stable `toolCallId`, tool input and output events; sources use `source-url`/`source-document`; custom data uses `data-*`; step/finish/error/abort events describe lifecycle, and `[DONE]` terminates the stream. Plain text transport supports text only, not tools. [Protocol](https://ai-sdk.dev/docs/ai-sdk-ui/stream-protocol)

## 3. Abstention, insufficient evidence and citations

**Documentation — Quote:** Sources says “dedupe them by `url`.” It renders `source-url` parts after text, counts actual sources, uses hostname when title is missing, and asks for accessible new-tab link announcements. This deduplicates source links, not semantic answer text. [shadcn Sources](https://ui.shadcn.com/docs/ai-elements/base/sources)

**Documentation:** InlineCitation associates a source with the sentence it supports and displays details on hover/focus; source listing belongs in Sources. The older Vercel page explicitly says automatic inline-citation integration with Streamdown/Response is unsupported and illustrates structured citation data with manual parsing. Neither component establishes that a cited document entails an answer or is applicable to a faculty/date/regime. [shadcn InlineCitation](https://ui.shadcn.com/docs/ai-elements/base/inline-citation), [Vercel InlineCitation](https://elements.ai-sdk.dev/components/inline-citation.md)

**Local:** Abstention already has explicit semantics: `not-determined` covers missing evidence and applicability uncertainties; `conflict` is separate. Generation stops before creating a model when status is unsupported or citations are absent, returning `fallbackReason='insufficient_evidence'` while retaining the existing result. A provider timeout/error is a different fallback cause. `planning-engine/normative.py:179`, `planning-engine/normative.py:189`, `planning-engine/rag_chain.py:73`.

**Local:** Possible repetition comes from a `not-determined` conclusion title, answer body, zero-source explanatory text, gap list and technical fallback reason. **Inference:** These sources support distinguishing one conclusion from supporting sources and specific gaps.
