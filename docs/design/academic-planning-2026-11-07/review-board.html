Recommended foundation: table-led operations with an inspector for the selected section.

Why it works

Fast comparison of courses, planned capacity, assignments and pending work. The proposal stays visible while the operator inspects an exception.

Tradeoff

Spatial relationships need a calendar view. The generated canvas is taller than the target viewport, and one row's duration summary needs correction against validated component data.

Strongest for placement review: a calendar with explicit current and proposed locations.

Why it works

A selected existing block has a clear duration, teacher, room and day/time form. Server validation decides whether the adjustment is accepted.

Tradeoff

Dense simultaneous sections require filtering and resource lanes. The six displayed sections are a subset; mobile needs an agenda/list.

Strongest for decisions: a version comparison with readiness evidence and one approval action.

Why it works

Makes the exact revision, changed sections and the consequence of approving visible together. Approval and publication remain separate.

Tradeoff

Less efficient for daily editing. Semantic version comparison and change reasons need a defined implementation; they are not existing API features.
