## Decisions and compatibility

Use one MR repository and existing session endpoints. Add an isolated `LocalProfileDashboardModule` for discovery and actor-scoped read projections only (no session-read/close route; logout is client-only). It imports MatriculaRegularModule once and never instantiates snapshot/operator modules. Public catalog contains only the four built-in actors; the chooser is the user-approved simple access form (one radio group of four profiles) and is explicitly a local demonstration, not authentication. Dashboard identity is held in one memory store, so router navigation shares a session and full reload returns login. Explicit renewal retains sessionId/startedAt; ordinary reads never renew.

The shell now has a fixed00:00:00 clock and useShellStudent/root loader assume anonymous formulario; RegularEnrollment keeps its own actor/session; SYN-SHELL-001 is a test harness identity. Replace those only in the isolated global profile path. Keep mock/legacy/private operator runtime and original wire unchanged. Use existing client sumApi as facade: active profile branch always calls new own API, with no mock fallback; root loader/login must avoid anonymous data requests. Guard all16 routes plus enrollment/report routes; caches and aborted late responses are scoped by generation/run/actor/session.

For academic screens use MR2 Context and committed Report rather than squeezing state into legacy DTOs that require unsupported official fields. Existing ApiResponseMap remains authoritative for compatible profile/form/table payloads; the additive typed map substitutes only six academic keys. Shared validators and existing panels, table, student summary, report view and result dialogs remain the implementation primitives. No generic redesign, second shell or second app.

Start an advancing synthetic clock at August11 09:00 Lima (`2026-08-11T14:00:00.000Z`, inclusive start of SYN-WINDOW-1, 2 h of open window per process), injected only by the isolated bootstrap; injected elapsed time controls tests. This is independent synthetic demo timing, not a new interpretation of F6. Documentary unknown hours/gaps remain intact. Login succeeds independently of academic access; registration still requires known matching scope, window, pre-enrollment enabled/complete, known offer/requirements. Existing synthetic institutional flags must be labeled as fixture assumptions and never inferred from an empty debt table or report download.

Reports/schedules use immutable committed rows and exact actor/run. No seeded report fallback. Logout is client-only: it immediately clears UI and caches with no HTTP call, and the server session expires naturally. It does not erase enrollment or uncertain intent (keyed by run/actor). Expired session can still recover a published MR2 result/report. Re-entry restores same-run same-actor pending identity; new run warns and clears old identity without resending. Late responses after logout/actor switch are discarded by client generation. Personal profile facts are an explicit unavailable state (`perfil` payload null). “Ver matrícula” as enrollment entry is a recorded local-only deviation from observed SUM public JS (`#irRepMat`→`v2/reportes/matricula`; entry `#iniciarMatricula`→`registro`).

## Dependency defects and separate legacy work

`rules.ts:dedupeCauses` and `matricula-regular.service.ts:sortedCauses` use component localeCompare, while shared orderedSet compares whole raw `code|courses|sections` strings with `>`. For the same supported code, a cause with empty courseIds and one with nonempty courseIds can order differently: component comparison puts the empty string first, while the full raw key compares the separator against the next ID character. Use actual supported simultaneous causes in the HTTP regression and these valid shape boundaries in the pure ordering test. Repair in LP-R1 with one shared backend helper using raw `<`/`>` comparison of the exact whole key, preserving dedup identity/source behavior and validators. Do not relax validator or change wire.
