## 60-30-10

Tokens already split neutral canvas/surface, muted text and borders, and one green accent. The
violation is usage: solid primary on every legacy button and several `--planning-primary` fills.
Screen tickets restrict the accent to the stage's primary action, the selected state and success icons.

Correction: `AcademicHistory` is the student SUM history screen, not part of this product; it is out of scope.

## Independent audit follow-up

Fixed: read-only disclosures inside locked fieldsets use native `<details>` (a `<button>` there is
disabled); non-success session messages become persistent warning toasts; premature fork toast removed;
activation opener stays enabled while its confirmation is open; disclaimer exposed to assistive tech;
`aria-selected` removed from plain table rows; step numbers dropped and scripts updated, including the
activation AlertDialog in `verify-cycle-complete.mjs`.

Open: `derivePlanningPrimaryAction('aprobacion')` returns `publish`, while the UI keeps publish as an
outline button with confirmation (design-direction: approval is the single primary decision). No 390px
check exists in `verify-planning-shell.mjs`. Verify scripts are syntax-checked only, not run.
