# Migración LangChain, Bedrock, pgvector y fuente S3 opcional

Decisión del usuario 2026-11-08: migrar PA-NORMATIVE-1 a LangChain, adaptadores intercambiables de modelos con AWS Bedrock predeterminado, pgvector y preparación para posible S3. Aplicar `mattpocock-skills:codebase-design` (proveedores inyectables detrás de interfaces pequeñas). Solo subagentes Codex, ninguna skill `sum-*` para desarrollo de producto.

## Comportamiento que se conserva

Contrato actual de consultas normativas, corpus público revisado, filtros previos de ámbito/periodo/fecha/tipo docente, citas validadas, metadatos/hash, abstención y conflictos detectados antes de truncar ocho citas. Preservar direcciones A/B/C de `docs/design-direction.md`, todas las interfaces SUM del alumno y solver/autorizaciones separados. Solo se autoriza cambio mínimo del consejero para indicar el modo real de generación. No leer datos-reales/, ni directamente ni vía índices/API/browser/caches/logs; no secretos/.env ni servicios del operador. Sin cambios del solver, cargas, aprobación o publicación.

## Arquitectura fijada para workers

### A — modelo y pipeline

Archivos exclusivos A: `planning-engine/rag_models.py`, `rag_chain.py` (si hace falta), `normative.py`, `advisor_agent.py`, pruebas de modelos/pipeline/normativa existentes y nuevas; `pyproject.toml`, `uv.lock`, `README.md`; extensión retrocompatible en `shared/programacion-academica-api.{mjs,d.mts}` y test dedicado del nuevo campo. No archivos B, UI o configuración raíz.

- `rag_models.create_chat_model(env=None)` mantiene firma `(model, provider_label)` y se reutiliza desde el consejero. Usa `init_chat_model`, default `bedrock_converse`, proveedores explícitos Ollama/OpenAI, modo disabled para pruebas. Conservar variables existentes y documentar alias/migración. Sin clave no cambiar silenciosamente a otro proveedor ni afirmar una llamada real. IAM sigue la cadena SDK en runtime autorizado; pruebas sin red usan `AWS_EC2_METADATA_DISABLED=true`. Conservar límites de tokens, timeout y privacidad.
- `rag_models.create_embeddings(env=None)` devuelve `langchain_core.embeddings.Embeddings`. Selección independiente por `SUM_RAG_EMBEDDING_PROVIDER`, `SUM_RAG_EMBEDDING_MODEL`, `SUM_RAG_EMBEDDING_DIMENSIONS`; default Bedrock y modelo Titan V2 verificado en documentación oficial. Proveedores LangChain oficiales Bedrock/Ollama/OpenAI y FastEmbed explícito local para tests/preparación existente. Dimensiones/modelo/proveedor forman identidad persistida del índice. No auto-descargar modelos al consultar. No inferir soporte de `init_embeddings`: usar fábrica built-in si soporta proveedor, clase oficial de integración si no.
- `rag_models.embedding_profile(env=None)` devuelve `{ provider: str, model: str, dimensions: int }`, sin secretos. Valores idénticos a `create_embeddings`, validados antes de indexar/buscar.
- Migrar recuperación a `Document`/`BaseRetriever`/`Runnable` y BM25 de integración LangChain con fusión de rankings; no envolver intacto el buscador manual fingiendo migración. Mantener entrada de pruebas inyectable de embeddings/repository y lógica normativa como reglas independientes. Fuente canónica de metadatos = corpus revisado; rechazar/desestimar documentos vectoriales desconocidos o cuyo contenido/hash no coincide. Filtro IDs aplicables en consulta vectorial ANTES de top-k, no filtrar solo después.
- Usar repositorio B mediante `create_vector_repository(embeddings, env=None, *, corpus_fingerprint: str)`. `search(query: str, eligible_ids: list[str], k: int = 8) -> list[Document]`; solo resultados del perfil/corpus activos. `index(documents: list[Document]) -> int` es operación explícita. Todos los Document llevan `metadata['id']` estable del artículo.
- `SUM_RAG_VECTOR_BACKEND=pgvector` es default. Sin DB configurada/no disponible, devolver estado/modo degradado explícito y evidencia léxica válida; no crear ni cargar un índice en memoria silenciosamente. No indexar, migrar ni crear tablas desde una petición. Para pruebas inyectar almacenamiento o seleccionar backend local explícito.
- Cadena de dos pasos: recuperar siempre antes de generación. Usar fábrica LangChain de chat para respuestas cuando configurada; validar salida estructurada y referencias contra citas recuperadas, preservar status/gaps y rechazar links/HTML/citas inventadas. En conflicto o información insuficiente conservar abstención, aunque el modelo proponga afirmaciones. Fallback extractivo identificado ante falta de proveedor, timeout o salida inválida; nunca afirmar una llamada o una respuesta sustentada inexistente. `SUM_RAG_GENERATION_MODE=extractive` permite tests sin cloud. No modificar fuentes/citas para acomodar una respuesta del modelo.
- Extensión opcional `AcademicNormativeResponse.generation?: { mode: 'llm-assisted' | 'extractive', providerLabel: string | null, fallbackReason?: 'not_configured' | 'timeout' | 'upstream_error' | 'invalid_llm_output' | 'insufficient_evidence' | 'disabled' }`. Validación estricta retrocompatible; omitir campos opcionales None. Campo permite indicar modo real en UI, no cuenta llamadas inventadas. Resto PA-NORMATIVE-1 no cambia. Raíz implementa visualización mínima tras integración.

### B — persistencia, ingesta y fuente opcional

Archivos exclusivos B: `planning-engine/rag_storage.py`, `rag_sources.py`, `rag_ingest.py`, nuevas pruebas `test_rag_storage.py`, `test_rag_sources.py`, `test_rag_pgvector_integration.py`, documentación `planning-engine/docs/storage.md`, scripts/compose propios de prueba en `planning-engine/` con nombres nuevos. No pyproject/lock/README ni archivos A/UI/shared/backend.

- `rag_storage.create_vector_repository(embeddings, env=None, *, corpus_fingerprint: str)` devuelve repositorio con `search`/`index` fijados arriba. Usa integración oficial `langchain-postgres` PGEngine/PGVectorStore (verificar API actual; evitar implementación vectorial SQL paralela). Config `SUM_RAG_DATABASE_URL`, `SUM_RAG_COLLECTION` prefijo seguro, y perfil procedente de A `embedding_profile`. Si A aún no está listo, pruebas inyectan perfil/dobles; no redefinir fábrica incompatible.
- Nombre/table/namespace deriva de perfil completo y fingerprint del corpus. Validar dimensiones e identidad del índice, impedir mezcla de modelos aunque tengan la misma dimensión; reindexado explícito en nuevo namespace. No sobrescribir ni borrar tablas existentes. Query no hace DDL ni escrituras. `index` es idempotente y documentada. SQL adicional parametrizado y nombres validados. No logs de DSN/credenciales.
- Comprobar pgvector real en contenedor propio, sin inspeccionar bases existentes. Docker disponible y puerto55432 comprobado libre por raíz. Autoriza crear contenedor aislado con imagen pública pgvector y datos públicos/sintéticos, credenciales ficticias locales; devolver nombre, puerto y DSN de prueba para integración raíz. No tocar contenedores/servicios existentes. Probar indexado, reinicio de objeto/repositorio, persistencia, filtro previo a top-k, idempotencia, perfil incompatible, fallo explícito. Dejar servicio de prueba disponible para raíz hasta entrega; documentar limpieza.
- `rag_sources.load_corpus(env=None)` retorna bundle curado existente con metadatos/hash. Default local. `SUM_RAG_SOURCE=s3` exige bucket+key explícitos y opcional VersionId/SHA256 esperado; GetObject de un manifiesto JSON revisado, lectura acotada y validación de hashes/URLs/metadatos. Sin enumerar buckets, crawlear, indexar documentos privados, subir, hacer red durante queries o inferir revisión de un objeto S3. Ninguna llamada S3 real sin configuración/autorización del operador: verificar con Stubber/fake y fuente local real. `boto3` requiere skill AWS SDK Python. Documentar S3 como fuente opcional, no almacenamiento vectorial ni reemplazo de pgvector. No URL presignada en citas; conservar URL pública aprobada.
- `rag_sources.corpus_fingerprint(bundle: dict) -> str` calcula huella determinista compartida por ingesta y servicio. El servicio lee solo bundle local revisado (`SUM_RAG_CORPUS_PATH` opcional de operador, default bundle actual), nunca S3 en una consulta. La CLI puede materializar un manifiesto S3 validado en un snapshot local explícito para usarlo como fuente canónica del servicio; no afirmar que cambiar bucket cambia automáticamente el corpus servido.
- `rag_ingest.py` CLI explícita: cargar bundle revisado local/S3, convertir en Documents, obtener embeddings de A, indexar B, imprimir perfil/namespace/cantidad sin secretos. No carga de dotenv, exploración del filesystem ni lectura de datos-reales/. Rutas de fuente solo en configuración de operador/CLI confiable, nunca request pública. Lectura S3/ingesta no forman parte de consultas.

## Dependencias y coordinación

A es único dueño de dependencias y sincronización uv; instalar lo necesario de integraciones LangChain comunitarias/BM25, langchain-postgres, psycopg binary/pool y boto3 si falta, conservando lock. B usa imports diferidos/dobles hasta disponibles; no competir por pyproject/lock o entorno. Checkout compartido conserva base extensa no versionada; sin commits/staging/reverts ajenos. No delegación adicional. Navegador y servicios React/Nest/Python anteriores pertenecen a raíz; B solo administra su contenedor nuevo pgvector. Ningún worker lee .env/secretos.

## Aceptación y verificación

1. Pruebas prueban componentes reales LangChain y adaptadores, Bedrock por default, cambio independiente chat/embeddings, fallos y fallback veraz. Sin llamadas cloud con credenciales ajenas; SDK/LLM con dobles. Consultar documentación actual Context7/oficial.
2. PGvector local real con corpus público, embeddings locales explícitos de LangChain, búsqueda híbrida y persistencia tras recrear repositorio. Cambiar modelo/dimensiones no reutiliza vectores incompatibles. Filtro previo no deja documentos fuera de ámbito desplazar los aplicables.
3. Mantener regresiones de límites/citas/conflictos saturados/inversos/fechas/tipo docente, seguridad de Markdown, respuestas obsoletas y API. Consulta no escribe ni descarga. Evitar medir deadlines CP-SAT mientras compila otro proceso.
4. Fuente S3 queda implementada y probada con doble, sin bucket creado ni acceso real; local funciona sin S3.
5. Raíz verifica React → NestJS → Python → pgvector con perfil local de prueba explícito y generación extractiva, y configuración Bedrock predeterminada con dobles. Credenciales/modelos reales Bedrock y bucket S3 quedan límites explícitos si no disponibles; no bloquear trabajo local ni pedir permisos repetidos.
6. Build/lint/proyectos afectados y tests relevantes; auditoría independiente Codex, hallazgos pequeños corregidos por raíz, máximo un ciclo por paquete. Entrega distingue configuración predeterminada de proveedor realmente ejecutado. Modelo/almacenamiento nuevos no implican vigencia normativa 2027 ni autorizaciones.
